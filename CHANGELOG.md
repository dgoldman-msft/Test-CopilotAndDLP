# Changelog

All notable changes to this project are documented here.

## Unreleased

- **Removed the last unverified DSPM fields: `PolicyName`, `RuleName`, `RuleActions`, `EnforcementMode`, `SensitiveInfoType`.** A real captured row confirmed these never appear on the `Export-ActivityExplorerData` "Copilot Interaction" activity and always returned `$null`; they were carried over from this module's original (pre-verification) field mapping. `Search-CopilotDlpDspmEvent`'s output, the `CopilotDlp.Evidence` format view's `Dspm` section, and the README's command-comparison table no longer reference them.
- **Fixed a real live-tenant bug: DSPM Activity Explorer rejecting the search window as a future date.** `Search-CopilotDlpAndDspmEvidence` built the DSPM query's `StartDateUtc` from the original (possibly stale) record start time even after unified audit had already found a more precise, correct activity time for the same `ConversationId` — this mattered most when a `ConversationId` is reused across multiple test runs in the same Copilot chat conversation, since the default `copilot-dlp-results.jsonl` lookup would resolve to an old run's start time. The DSPM lookup now reuses the same corrected `EffectiveStart` that DLP alert correlation already used. Separately, `Search-CopilotDlpDspmEvent` now clamps its search window's end time to 5 minutes before the current UTC time (instead of exactly now) and its start time to 5 minutes after the oldest allowed 30-day boundary, because `Export-ActivityExplorerData` can reject an end time that is too close to the real current moment as a "future date" due to clock skew.
- **Corrected the DSPM Activity Explorer field mapping using real, verified tenant data.** Earlier entries below claimed `Search-CopilotDlpDspmEvent` surfaced `EventId`, `Time`, `Location`, `Path`, `Actor`, `CorrelationId`, `EnforcementPlane`, `PolicyMatch`, `PolicyId`, `RuleId`, `RuleMatch`, `SITDetected`, `TrainableClassifier`, `ActionTaken`, `UserOverride`, `DetectedValuesForSITS`, `OtherMatchedConditions`, `UserRiskLevel`, `AppCategory`, `AppName`, `Plugins`, `Prompt`, `Response`, and `OverrideJustification`. Those were unverified guesses based on Purview portal screenshots and did not match the actual `Export-ActivityExplorerData` schema, which is why most DSPM fields in the combined evidence view appeared blank. A real captured `Export-ActivityExplorerData` row (an "AI interaction" activity for the `PurviewForAI` data platform) has now confirmed the correct field names, and the command's output, the `CopilotDlp.DspmEvent`/`CopilotDlp.Evidence` format views, and the test suite have all been rewritten accordingly:
  - **Removed** (never existed on the real row, always returned `$null`): `EventId`, `Time`, `Location`, `Path`, `Actor`, `CorrelationId`, `EnforcementPlane`, `PolicyMatch`, `PolicyId`, `RuleId`, `RuleMatch`, `SITDetected`, `TrainableClassifier`, `ActionTaken`, `UserOverride`, `DetectedValuesForSITS`, `OtherMatchedConditions`, `UserRiskLevel`, `AppCategory`, `AppName`, `Plugins`, `Prompt`, `Response`, `OverrideJustification`.
  - **Added** (verified against the real row): `RecordIdentity`, `ActivityId`, `AppLocation`, `AppHost`, `DataPlatform`, `ClientIP`, `AppIdentity`, `AppIdentityCategory`, `AppIdentityGroup`, `UserType`, `LicenseType`, `ThreadId`, `DLPEvaluationDeferred`, `MemoryUpdated`, `Messages` (message IDs and `isPrompt`/`JailbreakDetected` flags only), `AISystemPlugin` (`Name`/`Id` pairs), `HasWebsearchQuery`, `AreFilesReferenced`, `AreSensitiveFilesReferenced`, `SensitivityLabelIdsReferenced`.
  - `PolicyName`, `RuleName`, `RuleActions`, `EnforcementMode`, and `SensitiveInfoType` were initially kept as an unverified fallback from the module's original mapping; a subsequent real capture confirmed they don't exist on this activity type either and they have since been removed (see above).
  - Activity Explorer does **not** expose raw prompt or response text through this API; the `Prompt`/`Response` fields never existed and have been removed rather than corrected.
- `Search-CopilotDlpAndDspmEvidence`'s combined view now also shows `CorrelationMethod`, `SystemTags`, and a per-evidence `verdict`/user summary for `DlpAlert` entries, and `PolicyId`, `RuleId`, `Path`, and `TrainableClassifier` for `Dspm` entries.
- **Fixed a real device-code sign-in bug:** `Search-CopilotDlpAuditEvent -UseDeviceCode` was unconditionally suppressing console output during `Connect-ExchangeOnline`, which hid the device code and URL the user needs to complete sign-in, causing the connection to hang indefinitely. It now shows a visible "Complete the displayed device-code sign-in" message and leaves the console unsuppressed for device-code sign-in, matching `Search-CopilotDlpAlert`'s existing behavior. Default (non-device-code) sign-in still suppresses console output to avoid internal MSAL stack traces.
- `Search-CopilotDlpAndDspmEvidence`'s combined view now prints every field of each `UnifiedAudit`, `DlpAlert`, and `Dspm` item on its own line (`[N] Field: Value`), instead of one long space-separated line that word-wrapped unreadably across the console width.
- `Search-CopilotDlpDspmEvent` now surfaces DSPM for AI "AI interaction" fields: `UserRiskLevel`, `AppCategory`, `AppName`, `Plugins`, `Prompt`, `Response`, and `OverrideJustification`. `Prompt`/`Response` contain unredacted text; the command never logs them to a file.
- `Search-CopilotDlpAndDspmEvidence`'s combined view now includes a `Tested` section (from the submission's `ValidationRecord`: test user, start time, submission status, expected outcome, sensitive-text hash) alongside `UnifiedAudit`, `DlpAlert`, and `Dspm`, so one command shows what was tested, how DLP responded, and what DSPM captured together.
- **Fixed a real DLP alert correlation bug:** `Search-UnifiedAuditLog` returns `CreationDate` numerically in UTC but tagged with `DateTimeKind.Local`/`Unspecified`. Downstream `.ToUniversalTime()` calls (in `Search-CopilotDlpAlert` and the alert-time derivation in `Search-CopilotDlpAndDspmEvidence`) silently shifted this value by the local UTC offset, causing `Search-CopilotDlpAlert`/`Search-CopilotDlpAndDspmEvidence` to search the wrong time window and miss DLP alerts that actually exist. `CreationTime` is now explicitly re-tagged as UTC at the source without changing its value.
- Moved `Test-CopilotAndDLP.format.ps1xml` into its own `formats/` folder and updated `FormatsToProcess` accordingly.
- `CopilotDlp.AuditEvent` (`Search-CopilotDlpAuditEvent`'s output) now uses a full-detail list view showing every field, including `ValidationRecord` and `AuditData` expanded one key per line, instead of a 5-column table that hid most fields.
- `Search-CopilotDlpAuditEvent`, `Search-CopilotDlpDspmEvent`, and `Search-CopilotDlpAndDspmEvidence` now accept a `-ConversationId` obtained from anywhere (a saved JSONL run or the Purview alerts portal) with no `-StartDateUtc`: they look it up in the default `copilot-dlp-results.jsonl` first for an exact activity time, and otherwise search a widened `-ConversationIdLookbackDays` (default 7 days) window instead of the previous one/two-hour default.
- `Search-CopilotDlpDspmEvent` now surfaces additional fields observed on the Purview portal's alert-linked event "Metadata" tab: `EventId`, `Time`, `Location`, `Path`, `Actor`, `CorrelationId`, `EnforcementPlane`, `PolicyMatch`, `PolicyId`, `RuleId`, `RuleMatch`, `SITDetected`, `TrainableClassifier`, `ActionTaken`, `UserOverride`, `DetectedValuesForSITS`, and `OtherMatchedConditions`. `DetectedValuesForSITS` contains unredacted matched sensitive content; the command never logs it to a file.
- Added a combined list view for `CopilotDlp.Evidence` (`Search-CopilotDlpAndDspmEvidence`'s output) and a table view for `CopilotDlp.AuditEvent`, so one command shows unified audit, DLP alert, and DSPM summaries together, one item per line, for a single conversation.
- Fixed a silent-failure gap: `Search-CopilotDlpAuditEvent` now writes a warning showing the exact search window used when a single (non-polling) attempt finds no matching record, instead of returning nothing with no explanation.
- **Breaking:** renamed `Search-CopilotDlpEvidence` to `Search-CopilotDlpAndDspmEvidence` to better describe that it combines unified audit, DSPM, and DLP alert evidence.
- `Search-CopilotDlpAuditEvent`, `Search-CopilotDlpDspmEvent`, and `Search-CopilotDlpAndDspmEvidence` now default to `copilot-dlp-results.jsonl` in the current directory when called directly with no `-ConversationId`, `-UserPrincipalName`, or `-ResultPath`, and throw a clear error naming that missing default file when it doesn't exist. Pipeline input is unaffected.
- Added a format view (`Test-CopilotAndDLP.format.ps1xml`) so `CopilotDlp.AlertCorrelation` and `CopilotDlp.DspmEvent` objects print as one table row per item by default, instead of a multi-line list, making `DlpAlerts` and `DspmEvents` arrays readable in the console and in redirected/logged output.
- `Search-CopilotDlpAlert` now surfaces additional fields already present in the Graph `alerts_v2` response as top-level output properties: `Category`, `Categories`, `Description`, `RecommendedActions`, `InvestigationState`, `AssignedTo`, `Comments`, `SystemTags`, `DetectorId`, `Evidence`, `LastUpdateDateTime`, `ResolvedDateTime`, and `AlertPolicyTitle` (extracted from `additionalData`, more readable than `AlertPolicyId`).
- `Search-CopilotDlpAuditEvent` now supports `-PollForMatch` to retry the search on a doubling backoff schedule (bounded by `-PollIntervalSeconds` and `-PollTimeoutMinutes`) until a matching `CopilotInteraction` record appears, instead of a single search attempt.
- `Test-CopilotAndDLP` now accepts multiple `-TestSensitiveText` values (array or pipeline) and runs a full regression batch with a single Microsoft Graph sign-in reused across every submission.
- `Test-CopilotAndDLP` now retries transient Microsoft Graph `429`/`503` responses with exponential backoff instead of failing the run immediately.
- Added an `Integration` Pester tag (skipped by default; opt in with `$env:COPILOT_DLP_LIVE_TESTS = '1'`) covering `Search-CopilotDlpAuditEvent`, `Search-CopilotDlpAlert`, `Search-CopilotDlpDspmEvent`, and `Search-CopilotDlpAndDspmEvidence` against a real tenant.
- `Search-CopilotDlpAuditEvent` now accepts `ConversationId` directly, by pipeline, or from every record in a JSONL result file; returns only exact conversation matches; includes complete validation and audit payloads; expands nested `CopilotEventData`; and supports device-code authentication.
- Added `Search-CopilotDlpAlert` to retrieve Microsoft Data Loss Prevention alert summaries through Microsoft Graph `security/alerts_v2` and correlate them by test user and activity window.
- `Search-CopilotDlpAlert` now reports diagnostic warnings instead of returning silently when no alert matches a validation record.
- `Search-CopilotDlpAuditEvent` now converts Exchange Online authentication failures into concise, actionable errors instead of an internal MSAL stack trace, suggesting `-UseDeviceCode` as the fallback when the default (WAM) sign-in fails.
- `Search-CopilotDlpAuditEvent` now reuses an active, tenant-matching Exchange Online connection and token in the current PowerShell process instead of prompting on every search.
- Added `Search-CopilotDlpDspmEvent` to retrieve exact `ConversationId` matches from DSPM Activity Explorer through `Export-ActivityExplorerData`.
- Added `Search-CopilotDlpAndDspmEvidence` to return unified audit events, DSPM events, and Graph DLP alert summaries together for one conversation or an entire JSONL results file.
- Combined evidence retrieval preserves successful data sources and reports source-specific errors when unified audit, DSPM, or Graph alert lookup fails.
- `Search-CopilotDlpAndDspmEvidence` now accepts `ConversationId` alone, derives alert-correlation metadata from exact unified-audit or DSPM matches, searches every JSONL record, and reports wait-and-retry guidance for delayed DSPM or alert data.
- DSPM searches reuse an existing Security & Compliance session when available and otherwise call `Connect-IPPSSession` with isolated console and PowerShell streams, preventing internal MSAL call stacks from reaching end users and returning one concise action on failure.
- DSPM searches require ExchangeOnlineManagement 3.10.1 or later, update older installations automatically, and visibly report every new `Connect-IPPSSession` attempt.
- Module loading now reuses compatible modules already loaded in the process and reports one restart action when an older ExchangeOnlineManagement assembly can't be safely replaced, preventing duplicate-assembly call stacks.
- DSPM searches now clamp queries to the supported non-future 30-day window and return actionable service errors instead of secondary missing-property errors.
- Device-code authentication is now opt-in through `-UseDeviceCode`; otherwise `UserPrincipalName` is passed as the interactive Exchange account hint, and combined evidence searches propagate the explicit authentication choice.
- Graph device-code instructions remain visible so sign-in can be completed, and sparse DSPM activity records no longer fail when optional policy or rule fields are absent.
- Tenantless Graph authentication now uses the `organizations` audience, fixing device-code `AADSTS70011` failures caused by an invalid default authority.
- Combined evidence searches now isolate Microsoft Graph DLP-alert authentication in a child PowerShell process, preventing `Microsoft.Identity.Client` method conflicts with ExchangeOnlineManagement.
- Regenerated PlatyPS documentation for all exported commands, added complete examples and correlation explanations, and compiled external PowerShell help under `1.0/en-US`.
- Added `Get-CopilotDlpSensitiveInfoType`, a bundled catalog of 300+ Microsoft Purview built-in sensitive information type definitions, so any SIT can be discovered and referenced by name for use with `-SensitiveInfoTypeLabel`.
- `-SensitiveInfoTypeLabel` on `Test-CopilotAndDLP` is now a strict `ValidateSet` enforced against the bundled catalog (325 names, case-insensitive) with tab completion; unlisted values are rejected. The default changed from `Social Security Number` to the exact catalog entry `U.S. social security number (SSN)`.
- Added `Search-CopilotDlpAuditEvent` to correlate a `Test-CopilotAndDLP` run with Microsoft Purview unified audit log `CopilotInteraction` records.
- Added `-LogPath` timestamped progress logging (console and file) to `Test-CopilotAndDLP`.
- `Test-CopilotAndDLP` now checks for and installs `Microsoft.Graph.Authentication` automatically if missing.
- Added PlatyPS-generated command help under `docs/`.
